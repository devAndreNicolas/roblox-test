# Bingo Match Specification

**Status:** Draft for review  
**Purpose:** Define observable player and server behavior before implementation. This file is the behavior source of truth for the first Bingo match.  
**Related:** [MVP plan](../../docs/MVP.md) · [System design and assumptions](../../docs/SDD.md)

## Scope

One Roblox server runs one Bingo match at a time. Players join a lobby, wait for a group, play a shared-number match with individual cards, see the result, and return to the lobby. No persistent profile or economy is part of this spec.

## Terms

- **Lobby:** State where players wait before joining a match.
- **Participant:** A player included when a lobby countdown ends.
- **Match:** One call sequence and one card per participant, ending in a win or draw.
- **Called number:** A number already announced by the server during the active match.
- **Marked cell:** A player's card cell accepted as marked by the server.

## Requirements

### Lobby and match start

- **MUST** place each joining player in the lobby.
- **MUST** show the lobby player count and whether the server is waiting or counting down.
- **MUST** require at least two waiting players in a published server before starting a match.
- **MUST** start a visible 10-second countdown when at least two players are waiting.
- **MUST** cancel the countdown if the waiting count falls below two.
- **MUST** lock the participant list when the countdown ends.
- **MUST** keep players who join during a match in the lobby for the next match; they do not receive an active card or affect the current match.
- **MAY** use a one-player override in Studio for development. This override must not change the published-server minimum.

### Cards and calls

- **MUST** deal each participant one card generated by the server when a match starts.
- **MUST** use a 5×5 card with B=1–15, I=16–30, N=31–45, G=46–60, O=61–75.
- **MUST** select values without replacement within each column.
- **MUST** mark the center N cell free from the start.
- **MUST** create one shuffled sequence containing each number from 1 through 75 exactly once.
- **MUST** announce calls from the same sequence to all participants in the same order.
- **MUST** use a configurable initial call interval of 1.5 seconds.

### Marking and winner

- **MUST** let a participant request a mark by identifying a cell on their own card.
- **MUST** accept a mark only during an active match and only if the cell contains a called number or is the free center.
- **MUST** reject malformed cell identifiers, marks for another player's card, marks of uncalled values, duplicate marks, and mark requests after the match ends.
- **MUST** allow a player to mark an eligible number even if it was called earlier.
- **MUST** determine card completion and the winner on the server.
- **MUST** end the match on the first valid full card and accept no further marks for that match.
- **MUST** end with a draw if all 75 calls are exhausted before a valid full card.

### Results and player lifecycle

- **MUST** show the winner or draw for 8 seconds, then return remaining players to the lobby.
- **MUST** start a new 10-second lobby countdown only when at least two players are waiting again.
- **MUST** remove a leaving player's card and match state without interrupting the match for others.
- **MUST** provide joining players with lobby state sufficient to explain that they will play in the next match.
- **MUST NOT** persist cards, wins, or match state between server sessions.

## Scenarios

### A match begins after players gather

**Given** one player is waiting in the lobby  
**When** a second player joins  
**Then** both see a 10-second countdown  
**And** if both remain until it ends, both receive cards in the same match.

### Countdown resets when the group is too small

**Given** two players are in a lobby countdown  
**When** one leaves before it ends  
**Then** the countdown is cancelled and the remaining player sees that the server is waiting for another player.

### A late arrival waits for the next match

**Given** a match is active  
**When** another player joins the server  
**Then** that player sees the lobby and next-match status  
**And** does not receive a card in the active match.

### Valid and invalid marks

**Given** a player's card has a cell whose number has already been called  
**When** that player requests to mark the cell  
**Then** the server marks it once and updates that player's card state.

**Given** a cell's number has not been called  
**When** a player requests to mark that cell  
**Then** the server rejects the request and the authoritative card remains unchanged.

### First full card wins

**Given** the match is active  
**When** a participant's accepted mark completes their card  
**Then** the server records that participant as the winner and ends the match  
**And** all later mark requests are rejected.

### Exhausted calls produce a draw

**Given** the server has called all 75 values and no participant has a full card  
**When** the final call is processed  
**Then** the match ends as a draw and returns players to the lobby after the result display.

## Open questions

- Is a full card still the best first win condition after observing actual round duration?
- After the first friend test, should the call interval change from 1.5 seconds?
- Should the lobby eventually show a visible queue/party grouping, or is a player count enough?
